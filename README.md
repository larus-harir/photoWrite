# FRAME & WORDS

사진과 글로 4:5 인스타그램 캐러셀을 만드는 개인용 웹 편집기입니다. 로그인·백엔드·외부 AI API 없이 브라우저에서 사진 처리, 페이지 분할, PNG 출력을 수행합니다.

## 실행

Node.js 20.19+ 또는 22.12+가 필요합니다. 현재 환경에서는 Node.js 24 / npm 11로 검증했습니다.

```bash
cd /workspace/photoWrite
npm install
npm run dev
```

터미널에 표시되는 개발 서버 주소로 접속합니다. 클라우드 환경에서 제공하는 포트 접근 방식이 있다면 5173 포트를 사용합니다.

```bash
npm run build       # TypeScript 검사 + dist/ 프로덕션 빌드
npm run preview     # 빌드 결과 실행
npm test            # 페이지 분할 단위 테스트
npm run test:e2e    # 실제 Chromium 기능 테스트
```

잠금 파일 그대로 재설치하려면 `npm ci`를 사용하세요. E2E는 시스템 `/usr/bin/chromium`이 있으면 사용합니다. 없으면 `npx playwright install chromium`으로 브라우저를 설치하거나 `CHROMIUM_PATH`를 지정하세요. Playwright는 5173 포트의 기존 서버를 재사용하거나 자동 시작합니다.

## 사용법

1. 작업실에서 **새 프로젝트**를 누르면 사진·제목·본문·촬영 정보가 빈 상태로 시작합니다. **예시 불러오기**에서는 ‘꿈’, ‘이상은 이상’, ‘기억력’을 각각 새 프로젝트로 열 수 있습니다. JPG / PNG / WebP 사진을 올립니다. 드래그 앤 드롭도 지원합니다. 파일당 30MB, 최대 8천만 픽셀입니다. HEIC는 먼저 JPG로 변환하세요.
2. 작품 번호, 제목, 부제와 본문을 입력합니다. 촬영 정보 펼치기에서 연도·장소·카메라·필름·설명을 입력할 수 있습니다. 계정명 기본값은 `@cw_b_site`입니다.
3. 표지 → 사진 정보 → 본문 N장의 페이지가 생성됩니다. 빈 본문은 앞의 두 페이지만 만듭니다. 분량과 글상자에 따라 문단을 우선 보존하면서 자동 분할하고, 긴 문단은 줄 단위로 이어갑니다.
4. 본문 커서를 원하는 위치에 두고 **페이지 나누기**를 누르거나 별도 줄에 `---page---`를 입력해 강제 분할합니다. 구분자는 이미지에 출력되지 않습니다. 본문 페이지의 **원문에서 이 페이지 수정**은 원문 편집창에서 해당 부분을 선택합니다.
5. 썸네일로 페이지를 선택합니다. 표지는 드래그와 슬라이더로 크롭·확대·위치를 조절합니다. 사진 정보 페이지는 항상 원래 종횡비를 유지하는 contain 방식입니다.
6. 템플릿 & 스타일에서 제목·본문/부제 글꼴, 표지/본문 제목·부제 크기, 전체 본문 크기·줄 간격·여백을 조절합니다. 글꼴 기본값은 레퍼런스의 Noto Sans KR이며, 서체 미리 보기에서 선별한 다른 서체를 적용하고 기본값으로 복원할 수 있습니다. 오른쪽에서 선택한 본문 페이지에 크기·여백·제목 표시·세로 정렬을 별도로 적용할 수 있습니다. 넘치는 글은 다음 페이지로 옮기며 본문을 축소하거나 수정하지 않습니다.
7. 화살표로 페이지 순서를 바꾸고, 1080×1350 또는 2160×2700을 선택해 현재 페이지 PNG / 전체 페이지 ZIP을 저장합니다. ZIP의 번호가 현재 썸네일 순서를 따릅니다.

편집 화면은 입력 글자 15~16px, 안내 글자 12~14px로 표시합니다. 미리보기 기본 너비는 데스크톱에서 520~580px이며, 큰 게시물은 중앙 영역을 스크롤해 볼 수 있습니다. 아래의 고정 배율 도구로 20~200%를 조절하고, **화면에 맞춤**으로 전체 페이지를 확인하세요. 배율 숫자를 누르면 기본 100%로 돌아갑니다. 오른쪽 위 확대 아이콘은 패널을 접어 넓게 보는 모드입니다.

전체 본문을 편집하면 수동 페이지 순서는 초기화됩니다. 페이지별 스타일은 강제 분할 섹션과 자동 페이지 번호에 연결됩니다. 앞쪽 글의 분량을 크게 변경하면 같은 번호의 새 페이지에 설정이 적용될 수 있으니, **본문 → 스타일 → 최종 순서** 순으로 작업하는 것을 권장합니다.

## 구현 현황

| 범위 | 구현 |
| --- | --- |
| 사진·글 입력 | 사진 1장, 제목/부제/작품 번호, 촬영 정보, 저자 계정과 표시 설정 |
| Original Archive | PDF 기반 전체 사진 표지, 흰 여백 사진 페이지, 차콜 본문, 선택적 하단 그라디언트 |
| Editorial Journal | 아이보리 종이, 서체 선택, 선형 디테일과 편집 위계 |
| Film Archive | 인화지 여백과 큰 사진, 작품 번호·촬영 기록 중심 레이아웃 |
| 자동 분할 | 로컬 글꼴 로딩 후 Canvas 실측, 문단 우선, 안전한 긴 문단 분할, 명시적 구분자 |
| 수동 편집 | 원문 편집, 페이지별 본문 스타일, 강제 분할, 순서 변경 |
| 사진 구도 | 표지 드래그, 확대/가로/세로 위치, 초기화, 원래 비율의 사진 페이지 |
| 출력 | 두 정확한 픽셀 해상도, 개별 PNG와 일괄 ZIP, 순서·종류가 포함된 파일명 |
| 작업실 | 프로젝트 목록·신규 생성·검색·최근 수정/제목순 정렬·복제·삭제 |
| 글꼴 | 레퍼런스 기본 글꼴, 선별 서체 4종, 제목/본문 별도 선택, 제목/부제 크기 조절·복원 |
| 로컬 저장 | IndexedDB에 여러 프로젝트와 업로드 이미지·서체 설정을 독립적으로 저장·복구 |
| 오류 안내 | 손상/미지원/과대/완전 투명 이미지, 글꼴·저장·출력 실패, 낮은 사진 해상도 |
| 반응형 | 데스크톱 3열 편집기, 모바일 콘텐츠 패널과 내보내기 패널 |

작업실의 ‘예시 불러오기’ 또는 편집기의 ‘기존 게시물 살펴보기’에서 PDF 3개에서 추출한 사진과 글을 새 프로젝트로 불러올 수 있습니다. 기존 프로젝트를 덮어쓰지 않습니다. 작업실로 돌아갈 때 마지막 입력을 즉시 저장하고, 평상시에는 자동 저장합니다. 페이지를 새로고침하면 작업실 목록이 열립니다. 이전 버전의 단일 작업도 데이터베이스 버전 갱신 시 원문·사진을 보존해 프로젝트 하나로 옮깁니다. 사진과 텍스트는 사용자가 제공한 레퍼런스에서 추출한 것이며, 자동 생성이나 문장 재작성을 수행하지 않습니다.

## 사진·데이터 관련 주의

- 필터, 자동 색 보정, 채도·노출 변경, 샤픈, AI 보정을 적용하지 않습니다. 표지 하단 그라디언트는 별도 합성 요소이며 0%로 끌 수 있습니다. 크롭은 원래 비율을 유지합니다.
- PNG는 브라우저 Canvas가 렌더링한 픽셀입니다. 원본 파일 바이트·EXIF·ICC 프로파일을 그대로 보존한다는 뜻은 아닙니다. 브라우저·디스플레이의 색 관리에 따른 차이가 있을 수 있습니다. 원본 사진은 별도로 보관하세요.
- 고해상도 출력이 사진의 디테일을 새로 만들어 주지는 않습니다. 사진 픽셀과 실제 표지 크롭 확대율을 확인해 경고합니다.
- 사진·글은 서버로 전송하지 않습니다. 폰트도 앱에 포함되어 외부 Google Fonts에 요청하지 않습니다. 개발 서버는 앱 정적 파일만 제공합니다.
- 현재 브라우저와 사이트 주소에 여러 프로젝트를 저장합니다. 별도의 DB 서버·회원가입은 필요하지 않습니다. 다른 포트/브라우저/기기와 공유되지 않으며, 시크릿 모드·저장 공간 제한·사이트 데이터 삭제 시 복구하지 못할 수 있습니다. 자동 저장 상태를 확인하고 작업 종료 전에 PNG를 내려받으세요.

## 구조와 설계

```text
src/
  Studio.tsx                작업실 목록·프로젝트 생성/복제/삭제·예시
  App.tsx                   개별 프로젝트 편집기와 내보내기 흐름
  components/Typography.tsx 서체 선택·미리 보기·크기 조절
  lib/fonts.ts              선별 서체와 배포처 목록
  components/PageCanvas.tsx 실제 Canvas 미리보기
  lib/pagination.ts         원문 보존 줄바꿈·페이지 배치
  lib/render.ts             세 템플릿의 공통 픽셀 렌더러
  lib/media.ts              이미지/글꼴 로딩·검증
  lib/export.ts             PNG·ZIP 출력과 파일명
  lib/storage.ts            IndexedDB 저장
  types.ts                  프로젝트·페이지·템플릿 모델
  defaults.ts, examples.json PDF 기반 예제
  style.css                 반응형 편집 UI
public/demo/                PDF에서 추출한 예제 사진
references/                원본 기획서·PDF 3개·디자인 분석
tests/                    분할 단위 테스트와 실제 브라우저 검증
```

React + TypeScript + Vite, Canvas 2D, JSZip 및 공개 라이선스 한글 서체를 사용합니다. 텍스트 측정과 미리보기·출력에 동일한 Canvas 렌더러를 사용하기 위해 Konva 대신 Canvas 2D로 구현했습니다. 폰트는 npm 패키지로 자체 제공하며 텍스트에 필요한 서브셋의 로딩을 기다린 후 실측합니다. 줄을 자를 때 grapheme 단위를 사용해 조합 이모지를 분리하지 않고, 각 줄에 원문 조각을 유지해 공백과 개행 손실을 방지합니다.

## 검증

- 단위 테스트 8개: 한글·영문·한자·이모지, CRLF/빈 줄, 긴 단일 문단, 문단 경계, 강제 구분자, 빈 본문, 페이지별 배치, 순서 변경.
- Playwright 6개: 빈 작업실/프로젝트, 여러 프로젝트의 독립 저장·복제·삭제·검색, 기존 단일 작업 데이터 이전, 네 서체의 실제 Canvas 적용과 PNG 픽셀 일치, 실제 업로드와 드래그 크롭, 세 템플릿 전환, 원문 보존, 저장 후 새로고침, 페이지 재정렬, 원본 사진 픽셀 비교, 미리보기와 PNG의 디코딩 픽셀 일치, 두 출력 크기의 PNG 헤더, ZIP의 전체 파일 순서/해상도, 페이지별 설정·구분자, 손상/미지원 파일, 모바일 폭, 긴 제목·촬영 정보 경계와 계정명 중복 검사.
- 실행 결과는 `npm test`, `npm run test:e2e`로 재현할 수 있습니다. 브라우저 결과물은 무시된 `test-results/`에 기록됩니다.

## 후속 범위

여러 사진, 기기 간 프로젝트 동기화, 프로젝트 JSON/원본 사진 ZIP 백업·가져오기, 자유 배치 텍스트 박스, 임의 페이지 삭제, 직접 드래그하는 순서 변경은 아직 지원하지 않습니다. 현재는 고정된 표지/사진 페이지와 자동 생성 본문을 사용하며, 순서는 버튼으로 바꿉니다. PDF의 구조와 분위기를 재현했으나 Canva 편집 좌표까지 완전히 일치하는 복제는 아닙니다. 긴 입력의 전체 높이를 안전하게 맞추기 위해 제목과 촬영 정보의 글자 크기를 조절할 수 있습니다. 본문 글자는 자동 축소하지 않습니다.

## 선별한 공개 서체

임의 웹사이트의 글꼴 파일을 수집하지 않고, Google Fonts의 공개 배포본을 Fontsource npm 패키지로 선별해 앱에 포함했습니다. 모두 SIL Open Font License 1.1이며 `public/licenses/`에 원문을 함께 배포합니다. 앱 사용 중 외부 폰트 사이트로 사진·본문을 전송하지 않습니다. 미리 보기의 배포처 링크는 사용자가 직접 누를 때만 새 탭으로 열립니다.

| 서체 | 선택 이유 | 공식 배포처 |
| --- | --- | --- |
| Noto Sans KR | PDF 레퍼런스 기본, 담백하고 명료한 고딕 | https://fonts.google.com/noto/specimen/Noto+Sans+KR |
| Noto Serif KR | 정갈한 문예지·사진 에세이용 명조 | https://fonts.google.com/noto/specimen/Noto+Serif+KR |
| 고운 바탕 | 부드럽고 친밀한 일상 기록 | https://fonts.google.com/specimen/Gowun+Batang |
| IBM Plex Sans KR | 현대적인 편집·아카이브 고딕 | https://fonts.google.com/specimen/IBM+Plex+Sans+KR |

글꼴 변경 시 실제 선택 글꼴의 로딩을 기다린 후 글 너비를 다시 측정합니다. 본문 글자는 자동 축소하지 않고 다음 페이지로 넘기며, 긴 제목은 사진/본문과 겹치지 않도록 지정 크기 안에서 맞춥니다. 미리보기와 PNG는 같은 서체·크기·렌더러를 사용합니다.
