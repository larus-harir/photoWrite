# FRAME & WORDS — Codex 개발 명세서

## 0. 프로젝트 개요
- 개인용 사진 + 글 기반 Instagram 캐러셀 자동 제작 웹앱.
- 사진 업로드, 제목/부제/본문/촬영정보 입력 -> 템플릿 적용 -> 4:5 페이지 자동 생성 -> 미리보기 및 수정 -> PNG 개별 및 ZIP 일괄 다운로드.
- 사진의 원본 색감과 글의 원문을 존중한다. 사용자가 요청하지 않는 한 사진에 자동 보정/필터를 적용하거나 글을 재작성하지 않는다.
- 기존 PDF 3개(`꿈.pdf`, `이상은 이상.pdf`, `기억력.pdf`)가 원본 디자인 레퍼런스다. 반드시 레포지토리의 `references/` 디렉터리에 넣고 확인한다. PDF에는 편집 가능한 Canva 원본이 없으므로 화면을 기준으로 최대한 가깝게 재구성한다.

## 1. 기술/실행 환경
- React + TypeScript + Vite, Tailwind CSS 권장.
- 페이지 구성과 고해상도 이미지 내보내기에는 react-konva/Konva 권장. 다만 정확한 한글 줄바꿈과 글꼴 측정/렌더링이 일치하는지가 우선이다.
- ZIP 다운로드에는 JSZip, 로컬 프로젝트 저장에는 IndexedDB 고려.
- 1차 MVP에서는 백엔드, 로그인, 데이터베이스, 외부 AI API를 사용하지 않는다. 사진은 브라우저 안에서만 처리한다.
- `npm install`, `npm run dev`, `npm run build`로 실행되고 빌드되어야 한다.
- 마무리 단계에서 README에 개발/실행 방법을 기록한다.

## 2. 콘텐츠 입력 모델
- 작품 번호: 예) 007 (선택, 표시 여부 조절)
- 제목, 부제 (부제는 선택)
- 본문: 한국어/영어/기호/줄바꿈/빈 줄 지원, 원문 보존
- 촬영 연도, 장소, 카메라, 필름, 작품 설명(각각 선택)
- 저자 계정명: 기본값 `@cw_b_site`, 변경/숨김 가능
- 사진: 대표 사진 1장 필수, 확장 시 여러 장 허용
- 템플릿 ID, 템플릿별 스타일 옵션, 각 페이지 사진 크롭/위치, 수동 페이지 나눔, 페이지 순서

## 3. 템플릿 3종
### A. Original Archive (최우선)
- PDF 3작품의 공통 구조를 재현한다.
- 표지: 사진 전체 배경(cover), 좌측 상단 작품 번호, 좌측 하단 굵은 제목/부제, 하단 핸들. 가독성이 필요할 때만 하단 어두운 그라디언트를 적용하며 사용자가 조절/해제할 수 있어야 한다.
- 사진 페이지: 흰 배경, 넓은 여백 안에 원본 사진 비율을 최대한 유지해 배치, 하단 촬영정보, 하단 핸들.
- 본문: 거의 검은 차콜 배경, 밝은 글, 좌측 상단 제목, 넓은 여백, 본문 문단, 하단 핸들.
- PDF의 색감/서체/크기/여백은 시각 자료 기준으로 가까이 재구성하되 원본 Canva 요소의 정확한 수치나 서체까지 알 수는 없음을 감안한다.

### B. Editorial Journal (추천 기본형)
- 아이보리/오프화이트/차콜, 절제된 세리프 제목 + 읽기 쉬운 산세리프 본문.
- 문예지/독립 출판물 같은 위계, 여백, 선형 디테일. 사진 자체가 주인공인 감성.
- 가독성이 떨어지는 지나치게 작은 글자나 장식은 피한다.

### C. Film Archive
- 아날로그 사진집/컨택트시트/필름 인화지에서 착안한 편집 디자인.
- 사진이 크게 보이며 날짜/장소/장비/필름/작품 번호를 편집 요소로 사용.
- 과한 필름 프레임/먼지 효과는 기본적으로 넣지 않는다.

## 4. 출력 규칙
- 모든 페이지 정확히 4:5.
- 기본 1080x1350 px PNG, 고해상도 2160x2700 px PNG 선택.
- 여러 페이지를 순서대로 개별 PNG 또는 하나의 ZIP으로 저장. 예: `007_망원마음_01_cover.png`, `..._02_photo.png`, `..._03_text.png`.
- 다운로드 전 모든 폰트와 이미지의 로딩 완료를 기다리고, 투명/빈 이미지와 오류가 나면 명확히 안내.
- PNG 출력 시 글자 잘림, 줄 넘침, 이미지 찌그러짐, 워터마크 중복이 없어야 한다.
- 최종 PNG는 픽셀 렌더링 결과이며 원본 사진 파일 바이트/EXIF/ICC 프로파일을 그대로 보존하는 것을 의미하지 않는다. 업로드한 원본 파일은 필요하면 별도로 보관하도록 한다.
- 이미지를 임의로 업스케일해 디테일이 좋아졌다고 표현하지 않는다. 저해상도 사진이면 경고를 표시한다.
- 원본 이미지에 자동 필터, 미백, 채도, 샤픈, AI 보정 금지. 단 사용자가 조절한 crop/scale/position은 반영한다.

## 5. 자동 페이지 구성
- 기본 흐름: ① 표지 ② 사진 정보 페이지 ③ 본문 페이지 N장.
- 사진 설명만 있는 작품은 본문 페이지 없이 내보낼 수도 있도록 설계.
- 본문 편집창에 긴 글을 붙여 넣으면 지정된 글상자 크기·폰트·줄간격에 따라 자동 분할한다.
- 원래 입력한 줄바꿈과 빈 줄을 최대한 지킨다. 임의 문장 요약/수정 금지.
- 가능하면 문단 단위로 분할하고 한 문단이 페이지보다 길면 안전하게 줄 단위 분할한다.
- 글꼴 로딩 후 실제 측정값으로 줄높이/문장폭/페이지 높이를 계산한다.
- 글줄이 페이지 밖으로 넘어가지 않게 하고 자동으로 더 작은 글꼴을 적용하는 대신 기본적으로 다음 페이지를 만든다.
- 사용자는 `---page---` 같은 명시적인 수동 페이지 구분자를 넣거나 UI로 페이지 나눔을 설정 가능.
- 페이지마다 본문 정렬(위쪽/중앙 등), 제목 표시 여부, 폰트 크기, 여백 등을 조절할 수 있다.
- 자동분할 결과를 수동 수정해도 원본 글을 잃지 않아야 한다.

## 6. 웹앱 UX
- 데스크톱 중심 반응형 UI.
- 왼쪽: 작품 정보, 본문 편집, 템플릿, 스타일, 사진 추가/변경.
- 중앙: 실제 4:5 고정비율 페이지 미리보기.
- 하단 혹은 오른쪽: 생성된 페이지 썸네일 및 선택, 순서 변경, 페이지 수.
- 사진 드래그로 크롭 구도 조절, 확대/축소, 원본 비율 유지. 표지 cover 크롭과 사진페이지 contain 모드를 구분.
- 템플릿 전환 시 제목/본문/사진/촬영정보 손실 금지.
- 수동 페이지 수정 후 자동 재배치 동작을 사용자가 예측할 수 있게 만든다(초기에는 수동 분할 마커 기반으로 구현).
- 작고 일관된 컨트롤, 밝은/어두운 프리뷰 대비가 잘 보이는 웹 편집기.
- 필요한 곳에만 설정을 노출하는 간단한 UI를 우선한다.

## 7. 저장/불러오기
- MVP: 새로고침으로 즉시 손실되지 않도록 브라우저 로컬 저장 지원(IndexedDB 권장, 이미지 Blob 포함).
- 다른 컴퓨터로 이전하기 위한 프로젝트 내보내기/불러오기는 2차 범위로 두되 데이터 모델 확장성을 고려한다. 가능하면 JSON + 원본 이미지 묶음 ZIP 형태.
- 업로드 사진은 외부 서버로 자동 전송하지 않는다.

## 8. 구현 순서
1. 프로젝트 초기화 및 UI 기본 골격, 데이터 타입 작성.
2. Original Archive 3종 페이지(표지, 사진, 본문) 실제 렌더링.
3. 사진 업로드/크롭/촬영 메타데이터 입력.
4. 본문 자동 줄바꿈/페이지 분할 및 수동 구분자.
5. 1080x1350 및 2160x2700 PNG, ZIP 다운로드.
6. Editorial Journal / Film Archive.
7. 로컬 저장, 오류 처리, 반응형 개선.
8. 검증과 문서화.

## 9. 완료 검증(중요)
- PDF 3작품을 시각 레퍼런스로 사용하여 기존 템플릿이 구조적으로 매우 유사한지 확인.
- 4:5 정확한 픽셀 해상도 확인.
- 한국어 긴 글, 빈 문단, 강제 줄바꿈, 특수기호, 긴 제목, 여러 페이지 글에서 잘림/겹침 없음.
- 브라우저 미리보기와 다운로드 이미지 내용·페이지 순서 일치.
- 밝은 사진에서도 표지 제목이 읽히고, 사진 페이지에서 원본 비율이 깨지지 않음.
- 폰트 로딩 실패, 작은 원본 사진, 손상된 파일/미지원 포맷, 메모리 부족 등에 사용자 친화적 오류 안내.
- `npm run build` 성공, 기능별 기본 테스트(페이지 분할 테스트 등) 작성.

## 10. Codex 작업 지침
- 우선 구동 가능한 MVP를 실제 코드로 완성한다. 가짜 버튼/기능 없는 미리보기를 최종 상태로 남기지 않는다.
- 구현에 앞서 위 사양을 충족하는 간단한 폴더 구조와 개발 순서를 정리하고 바로 구현을 시작한다.
- 기존 세 PDF의 시각적 특징을 실제로 확인한 뒤 디자인에 반영한다. PDF를 확인할 수 없다면 무작정 재현했다고 말하지 말고 레퍼런스가 필요함을 안내한다.
- 1차 구현은 Original Archive, 긴 글 자동분할, PNG/ZIP 내보내기에 집중한다.
- 작업 후 설치 및 실행 명령, 구현한 기능, 아직 안 된 기능, 테스트 결과를 간결히 보고한다.
